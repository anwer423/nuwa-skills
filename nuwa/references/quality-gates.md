# 交付前验收清单

逐条打勾，任一条不通过就不要交付。

## 触发

- [ ] 只看 `description` 就能判断该不该用这个技能，不需要读正文
- [ ] description 里含用户真实会说出口的词，不是自造术语
- [ ] 和已装技能没有明显触发词撞车（撞了就在 description 里写清边界）

## 结构

- [ ] 目录名 = `name`，kebab-case
- [ ] frontmatter 只有 `name`、`description`
- [ ] `python scripts/validate_skill.py <skill-dir>` 无 error
- [ ] 技能目录内没有 README / CHANGELOG / 安装指南
- [ ] 没有 TODO、占位符、模板残留文件
- [ ] 没有空目录、`.pyc`、缓存

## 内容

- [ ] 正文 ≤ 500 行，且全部是「AI 自己想不到」的信息
- [ ] 每条指令都能落到具体动作或具体判据，没有「注意细节」这类空话
- [ ] 口径、单位、时间范围、字段名写死，不留「按实际情况」的模糊处
- [ ] 提到的每个 references / assets 文件都说明「什么时候读」
- [ ] 没有把私有路径、账号、密钥、内部链接写进技能（要写就写占位符 + 获取方式）

## 脚本

- [ ] `scripts/` 里每个脚本都真跑过至少一次，输出符合预期
- [ ] 参数有默认值或明确报错提示，不静默失败
- [ ] 只依赖标准库或明确声明了依赖
- [ ] 覆盖文件、删除文件这类破坏性动作有确认或 `--force` 开关

## 可用性

- [ ] 用一句真实用户会说的话试触发，确认能命中
- [ ] 按 SKILL.md 从零走一遍流程，中途没有卡在「文档没说清」的地方
- [ ] 已经想好下一步迭代要改什么（不要求，但强烈建议记一条）

## 收尾

- [ ] 技能目录整体复制或推送后，在目标环境能被加载（放 `.skills/` 或 `workspace/.user_skills/`）
- [ ] 仓库根的 README 写了安装方式和最少一个使用示例
